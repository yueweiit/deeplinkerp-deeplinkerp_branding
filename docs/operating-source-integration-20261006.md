# 运营支出原始来源接入

## 范围与复用

沿用 `operating-expenses` 原有页面、来源缓存、财务映射、事件和原生凭证草稿服务，不另建请款系统。当前入口为“中国财务 → 支出管理 → 运营支出”，“支出管理”位于“银行与对账”和“凭证明细与历史”之间。分组由 `china_finance/setup/install.py` 生成，`deeplinkerp_branding/operating_navigation.py` 同步时保留该分组及子项位置；普通会计工作区仍沿用科目表后的入口。请款网站继续保留。

只接入 2026 年中国执行地区的付款申请及费用报销，使用七个运营审批流程码；采购、墨西哥和备用金不在本轮范围。运营来源审批及归档附件改用 OA 只读 HTTP API，出纳网站仍提供付款、审批任务和申请人归属证据。采购的 OA 数据读取仍使用独立的既有路径。

## 数据口径

- OA 原单决定申请身份、类型、金额、币种、摘要、收款人及审批状态。只有 `COMPLETED + agree` 可办理；拒绝、撤销及在途仍保留审计展示。
- 出纳逐笔付款是付款状态的证据；“同意付款”和计划付款日期均不代表已付。缺失或冲突显示“付款待核对”，已付/待付为空，不伪造为零。
- 当前员工目录仅补充组织归属。明确部门经已确认法律公司映射接入；身份含糊、混合组织或未匹配记录仅管理员核对，不猜公司。
- 同一 OA corporation/instance 始终保留同一已缓存根，出纳匹配变化不得新增重复申请或重用不同审批的历史根。人工映射及凭证事件保留。
- 出纳审批补充原文可审计查看，但不改变 OA 原费用确认指纹；真实原单金额、公司及审批变化仍会使既有确认失效。
- 附件按原单精确身份及当前 SHA256/长度校验，通过 OA HTTP 下载；退役或来源删除的附件不可下载，预览件及质量未知文件在明细中标记；不修改原始归档。
- 每 15 分钟按企业及流程码分页全量重扫，仅写变化指纹；失败不推进完成水位。业务编号兜底关联仅在同企业按编号精确查询证明唯一后使用，精确实例身份关联优先。

## 安全边界与兼容

同步只保存非会计来源缓存。不会自动生成、提交凭证，不会付款、生成 GL、结账或创建供应商/员工/科目。财务逐笔确认映射及实际发生后，现有服务只能保存原生 Journal Entry 草稿。

旧 `cashier` 来源模式仍供既有部署/QA 使用；在全部调用方切换并完成历史根、人工映射及事件一致性验收前保留。`oa_cashier` 只替换接入来源，不复制凭证、导出或列表流程。模式兼容层退出须核实无旧配置/调用，并验证存量事件可继续读取。

## 发布与剩余技术债

必须先本地及独立复核通过、冻结 SHA、远端 CI 通过，再用现有带锁/备份/严格审计的脚本发布。沿用 CRM/China Finance 已部署基线。代码发布完成后确认 OA API 连通、企业 ID、公司映射，预览并启用同步，复核线上列表、明细、附件与导出。OA 新接口自身不做调用方鉴权，须在网络/反向代理层限制访问，不能直接暴露到公网。

## OA HTTP 读取配置（2026-11-03）

ERP 适配入口为 `deeplinkerp_branding/services/operating_oa_http.py`；只有站点配置 `operating_expense_source_mode=oa_cashier` 才会调用它。`operating_expense_oa_api_url` 默认 `http://8.135.70.135:3005`，站点配置可以覆盖。`operating_expense_oa_corp_ids` 接受企业 ID 数组或逗号分隔字符串；未设置时使用运营来源默认企业 ID `ding144583309b2fb01c35c2f4657eb6378f`，不继承海外成本核算的企业配置。配置遗漏已缓存企业时同步报错，不自动撤回旧数据。出纳 Bearer 密钥仍由原有设置管理，OA HTTP 接口无需密钥。

“运营支出同步设置”显示当前来源模式及对应的实际审批来源地址。若显示旧出纳地址，表示站点仍在 `cashier` 模式，或服务尚未运行包含来源模式字段的新版本；点击手动同步不会因此切换到 OA。切换为 `oa_cashier` 后，审批来源地址显示 OA API 地址；配置原有出纳密钥后，出纳接口才会补充付款等证据。站点模式变更须在目标环境核对后执行，不能通过修改页面显示地址替代。

`oa_cashier` 模式下缺少出纳密钥时，OA 审批与归档附件仍可预览和同步；付款、补充审批任务及员工归属不猜测，保留待核对状态，付款登记资格保持关闭。后续配置出纳密钥后须重新预览和同步，使补充证据按来源身份核对后补入。旧 `cashier` 模式仍要求出纳密钥。

同步读取 `/api/v1/approvals` 与独立的 `/api/v1/attachments` 分页流；附件下载读取 `/api/v1/attachment-content`，不再从运营服务连接 OA PostgreSQL 或 MinIO。旧 PostgreSQL 三字段游标在下次同步时从头重扫；公司映射、来源根及财务事件保持原值。对外下载继续检查来源读取权限、实时版本、精确 OA 身份、归档状态、20 MiB 上限及 SHA256/大小。该 API 返回本地归档快照，不保证钉钉实时状态；服务器联调和生产验证尚未执行。

远端游标过期时，运营同步从首页重扫并仅在成功后替换检查点；整轮核对对全扫漏掉的缓存身份再做精确查询，查询失败时停止撤回判定。附件展示质量字段不改变历史财务确认使用的附件版本；批量同步在同一任务内复用完整附件清单，单笔财务确认和下载仍按实例重新读取。编号兜底关联只查询候选编号，429 限流保留检查点并等待后续同步重试。

当前仅有 `http://8.135.70.135:3005` 公网地址，接口本身无调用方鉴权，审批及附件在传输中也未加密。ERP 端不能单方面补足 HTTPS 或服务器访问限制；生产启用前应由 OA 服务提供 HTTPS 或内网入口，并限制来源 IP。此项为尚未解决的部署风险，不视为本地代码验证通过。

未处理：请款网站退役、历史年度接入、备用金、自动费用科目/往来映射及正式凭证过账。目录无唯一身份、付款无逐笔证据和来源冲突需人工核对，不自动修复历史业务数据。
