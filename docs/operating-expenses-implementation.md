## CN 只读审批工作台（2026-11-20）

与新版 Budget 联合安装时，CN 的总览、台账、分类分析及核对页面由 `budget/public/js/cn_approval_workbench.js` 实现，统一读取共享审批 HTTP 接口中的预算、运营和采购数据。品牌 App 仅通过 `public/js/china_expenses_page.js` 选择资产、处理路由切换，并提供现有 HTTP、字段、分类及原审批链接工具；MX 页面和服务未改动。新只读导航不会被 `operating_navigation.ensure_cn_cash_journal_navigation` 自动插入记账入口。四个现有 Page 路由继续使用，旧薪酬路由显示分类分析。

范围、权限、统计口径和配置以 [Budget 工作台文档](../../budget/README.md#cn-只读审批工作台2026-11-20) 为单一入口。以下原运营办理、预算台账与日记账说明属于保留的独立服务/旧页面兼容能力，新工作台不再调用其付款办理和台账同步 UI。回归入口：`tests/regional-expense-page-loading.test.js`、`tests/test_operating_expense_navigation.py`；同步和办理服务仍按原权限执行。

## CN 运营支出合并（2026-11-19）

“运营支出（CN）”的概览、明细、支出分析和数据核对已接入原中国财务入口使用的 `Operating Expense Source`。复用 `services/operating_expenses.py` 的权限过滤、当前公司归属、ERP 付款覆盖、导出与原办理抽屉；不复制来源数据，不自动确认公司、登记付款或生成凭证。旧 `operating-expenses` URL 保留兼容，CN 导航可用时从 Accounting/China Finance 移除系统管理的重复入口及空“支出管理”分组，保留用户自定义筛选链接；没有 CN 导航的独立安装保留原入口。

- 运营支出及“全部审批表”读取同一套现有国内申请；“全部”明确仅统计运营支出，预算通过独立选择展示，采购统计尚未接入。预算导航和数据适配由 Budget App 负责，薪酬分析缺少可靠分类仍显示待接入，不从摘要猜测工资。
- 日期口径默认使用申请日期，默认中国时区当月及全部审批状态；按原始币种分列，暂不套用 MX 的审批月汇率。已核实付款为所选申请累计付款，不代表本期支付或总账已入账费用。
- 概览、分析按公司、申请月份、财务申请类型汇总；复用精确十进制汇总。未知付款保持待核对并显示可确定部分，负数异常不参与正常合计；未映射或过期归属单独列组，不计入具体子公司。
- 明细每页 20 条，支持快捷状态、关键词、归属状态和申请类型；数据核对使用原 reconciliation 规则。查看审批、付款明细、公司复核均调用原抽屉，继续受后端财务权限与版本校验约束；保存后重读数据。导出使用同一筛选和原生导出权限，覆盖全部匹配记录。
- `cn_filters`、日期与审批表偏好独立于 MX。公司选择与原运营服务一致，读取原生权限过滤的 Company 范围，不因国家或集团标记隐藏已有法律公司归属。预算公司取本地台账/额度来源名称，按原名精确筛选，不猜测与法律公司的对应关系；采购页面仍待接入。

代码入口：`public/js/china_expenses.js`（生命周期与筛选）、`china_operating_expenses.js`（现有服务适配与展示）、`services/operating_expense_analysis.py`（纯汇总）、`operating_navigation.py`（导航合并）。`budget.setup.apply_budget_nav` 创建可用 CN 侧栏后再次调用合并，兼容首次安装顺序；`restore_budget_nav` 在移除 CN 侧栏后恢复尚存品牌 App 的备用入口，无需再执行迁移。公司选项初始化与数据刷新分别校验请求代次及当前路由，旧页面的延迟响应不能消耗新页面的 `cn_filters`，兼容原生路由二次序列化。相关回归：`tests/china-operating-expenses.test.js`、`tests/test_operating_expense_analysis.py`、`tests/test_operating_expense_navigation.py`。

CN/MX 页面加载器向 `frappe.require` 传递不带查询参数的资源路径，由框架添加缓存版本；共用资源使用相同路径，避免重复执行。当前 Frappe 的资源类型识别不兼容手工 `?v=` 参数，会在页面初始化前抛错。原生加载链路及两种访问顺序的回归见 `tests/regional-expense-page-loading.test.js`。

## CN 预算导航整合（2026-11-19）

取消单独“预算管理”分组；选择审批表“预算”后，概览/明细/核对委托 `window.CNBudget`，预算明细区分台账和额度。统计报表新增“预算执行分析”（原 `budget-dashboard` 路由）。预算数据、额度权限、报表及同步规则由 `budget/api/cn_workbench.py`、`budget/public/js/cn_budget.js` 实现，详见 [Budget 说明](../../budget/README.md#cn-预算整合2026-11-19)。原生 ERPNext Budget 不受影响。

`china_expenses.js` 只负责公共框架和上下文传递：预算日期归一为完整月份、固定 CNY，记住日期/公司/审批表及额度页签；切换业务时清除不兼容的公司/部门筛选；预算报表切换到运营支出时返回概览。同步入口按当前业务调用原运营工作流或 `BudgetLedgerSync`，预算按钮明确为“同步预算台账”。切换路由和筛选会销毁报表图表、失效旧请求，避免迟到响应覆盖新页面。预算额度和计划均不并入实际支出合计。

预算执行分析的已审批支出由 `services/operating_budget_report.py` 提供内部读取入口：先经过运营列表的原生公司/字段权限，再按可读父单 ID 批量投影 OA 企业身份及 `workflow_summary.reporting`，不公开原始 JSON。`operating_oa_workflow.py` 在同步快照中保留审批创建/完成时间、发起部门 ID/名称及节点起止时间，不增加用户信息或付款推断；正常同步结束核查会补齐已有记录的时间快照。报表由 Budget App 按审批完成月份月初汇率折算 CNY，运营工作台本身继续按原币分列；具体口径及不可用状态见上述 Budget 文档。

## CN 同步设置（2026-11-19）

复用原运营同步服务与 `settingsWorkflow`，使用原生居中 Dialog；MX 模板字段映射、财务节点与地区排除规则不套用到 CN。前端入口为 `public/js/operating_expense_settings.js`、`operating_expense_drawer.js`，CN 页面与旧运营页面共用“同步设置”和“同步数据”两个独立入口。

- 设置弹窗只编辑审批模板和公司历史名称，底部仅保留“保存设置”，保存成功后关闭并刷新页面。页面独立“同步数据”按钮打开只读同步控制窗口，承载预览、明确确认启用、停用及“立即同步”；两个入口均仅供系统管理员使用，打开窗口不会自动请求 OA 或导入数据。

- `Operating Expense Sync Settings.approval_templates` 使用子表 `Operating Expense Approval Template`，维护启用状态、模板名称和唯一 `PROC-…` 流程编码，上限 100 行。首次迁移保留原七个模板及其顺序、公司映射和同步开关；初始化钩子在原生索引等元数据钩子之后执行，避免数据写入干扰后续 DDL 校验。
- 已保存的流程编码不能删除或替换，历史模板使用停用。停用只停止导入新申请；同步完成时，历史核查仍按原身份刷新已有申请的审批状态、金额和附件，并保留付款关联及来源变化后的财务复核规则。复用 `services/operating_expenses.py::_oa_source_items` 统一解析，附件按模板批量读取，未变化的记录不重复写入；来源撤回、移出范围及快照时间边界校验继续生效，不因模板停用而批量撤回。中国地区、2026 年申请窗口和付款申请／费用报销类型校验保持原状，新增模板需沿用现有字段契约；预算与采购数据未在此接入。业务时区仍为只读 `Asia/Shanghai`。
- 公司历史名称按 ERP 法律公司折叠显示，可在公司组内添加别名。名称仅作明确映射，不模糊猜测归属；单据级 `source:` 覆盖不进入历史名称编辑，保存时保留，新增或变更必须从对应申请核对。既有财务确认及其公司保护不变。
- `get_sync_settings` 新增 `approval_templates`、`config_version`、`business_timezone`；`save_sync_settings` 增加可选模板参数和预期配置版本，旧调用保持兼容。新界面每次保存携带版本，发生并发更改时拒绝覆盖。保存仍停用同步、清空游标和预览，必须重新预览并显式确认启用，不自动同步或生成财务单据。
- 模板和公司配置均进入预览指纹；远程预览期间不持有配置写锁，返回后锁定并核对配置版本。HTTP 分页游标绑定企业与模板顺序指纹；旧 HTTP 游标仅在原默认模板顺序下兼容，原 PostgreSQL 游标从头重扫。
- 设置弹窗的关闭按钮与 Escape 共用未保存确认；移除原生按钮的自动 dismiss，取消关闭保留输入，确认后才销毁控件，保存期间不能关闭。
- 核心实现：`services/operating_sync_config.py`、`operating_expenses.py`、`operating_oa_http.py`、`operating_oa_source.py`。共享 OA 解析函数保留原默认参数，采购旧调用不变。新增界面与校验文案覆盖中、英、西语。

本地 `dev.localhost` 已备份并迁移；回归覆盖配置冲突、历史模板停用、国家/类型隔离、旧游标及公司覆盖保护。浏览器真实读取现有设置，模板保存／预览／启用使用模拟响应验收，未为测试执行 OA 同步或改变现有同步开关。生产尚未部署。

## 已确认边界

- 保留请款网站，ERP 只同步运营付款申请、费用报销和付款依据。
- 不登记第二份付款，不自动提交、生成总账或结账。
- 财务在侧边面板维护分类、公司、科目及辅助核算，预览后生成原生 Journal Entry 草稿。
- 费用确认与逐笔付款结算独立关联，稳定来源事件防止重复生成。
- 缺失分类、公司、金额、往来或汇率时明确提示，不猜测。

## 来源契约

`GET /api/integrations/erp/operating-expenses` 使用单用途 Bearer token 和明确页签范围；默认禁用。
响应 schema_version=1，申请 source_id 使用逻辑根，payment source_id 使用付款根，版本覆盖申请、付款和附件。
申请分类只接受 payment、reimbursement、unclassified。原始来源没有类型时必须待分类。
公司原值与来源页签只用于人工映射，不直接等同 ERP 法律主体。
同步分页使用 until 水位，包含付款及附件变化；不会更新源网站摘要。
当前可编辑申请金额仍是业务金额；原始申请金额字符串另列保留，并报告既有 SQLite REAL 精度损失，不用历史原值覆盖人工修改。
不同时间的逻辑副本若来源身份或法律公司不一致，将阻断；付款附件按付款根与文件摘要去重。

### 出纳办理统计口径

CN 运营支出新增 `basis=cashier`（出纳办理日期）。从同一 OA 原单的 `tasks` 读取已核实存在的“出纳”“CN 出纳Cajero”节点；节点须全部完成且 `AGREE`，转交记录不计入，存在未完成、拒绝、缺失或无时区时间的节点时不纳入。每笔申请按最后完成时间的中国时区日期统计一次申请金额，页面标为“出纳已办理金额”。已撤回、终止、拒绝或来源字段冲突的申请排除；月度分组、明细和导出使用相同口径，申请日期早于所选范围的申请仍可按办理日期计入。公司范围沿用原生权限和已确认归属。

### CN 手工日记账

CN 导航在“支出明细”后增加“日记账”，`china-cash-journal` 提供逐行编辑表格，主要列为日期、钉钉审批号、收入/支出、金额和说明；公司和币种在表格上方选择。账户不再要求填写，钉钉审批号与说明可留空。同一审批可登记多笔流水，因此审批号不设唯一约束，也不据此自动关联 OA。

底层沿用 `CN Cash Journal Entry`，收入/支出使用稳定编码 `income` / `expense`。金额为最多两位小数的正数，阻止原生 Currency 序列化时会丢失分位的超大值；按所选币种记录，不执行换算。公司 Link 和原生读写 API 保留角色、公司用户权限及修改时间冲突校验。表格分页读取，原生保存保留原记录的附件、备注和其他未展示字段；失败保留输入，同一行保存期间阻止重复提交，未保存修改会阻止刷新/分页/筛选。

这是可手工新增和修改的独立流水记录，不可提交；保存不会创建总账分录、凭证、OA 来源或付款事实，也不混入 OA 支出/预算统计。财务用户、财务经理和系统管理员可登记；删除仅授权财务经理/系统管理员。`track_changes` 保留修改记录；原生详情页继续支持附件、打印和导出。历史账户字段隐藏并保留数据。记录编号格式为 `CNCJ-{YYYY}-{#####}`。
