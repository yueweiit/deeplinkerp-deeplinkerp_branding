# 国内银行日记账导入

在「支出管理 → 日记账」选择公司、币种和银行科目。页面按日期和原表顺序显示。每页 20 行，跨页不重置余额。未分配账户的旧流水仍可查看。不能读取账户完整前序流水时，不展示账户余额。

期间可选全部月份、单月或连续的起止月份。起止月份都包含在内。本期收入和支出统计所选期间内可见的全部流水，不限于当前页。要核对银行余额，请先选择一个银行科目。期初余额取期间开始前的结余，无流水月份也会承接上期余额。筛选和翻页都不会修改流水。

本导入器仅供站点管理员处理完整、人民币、零期初的银行日记账。按 CSV 原文保存三级分类和钉钉单号。期初说明、期末合计、空行不入账。模板中不支持的非空列会阻止整批导入。它不生成凭证、银行交易或预算记录。

1. 将本版本纳入品牌 App 的正常 Docker 镜像构建。确认运行镜像与源代码一致，不要覆盖生产的其他定制。
2. 在测试环境验证字段迁移。分项发布时可用 `bench --site SITE reload-doc deeplinkerp_branding doctype cn_cash_journal_entry` 同步标准定义，并刷新页面缓存。整站迁移受到其他应用检查阻止时，先报告并解决该发布问题。
3. 确认账簿标题、公司和本公司内启用的人民币银行明细科目。不要从摘要猜测目标账户。
4. 使用站点的 `bench execute deeplinkerp_branding.services.cn_cash_book_import.import_journal`。用 `--kwargs` 传入 `path, company, account, title, expected_rows, expected_closing`。输入可来自容器标准输入（`path=/dev/stdin`）。不把流水放入 Git、构建上下文或公开附件。
5. 先使用默认的 `apply=False`。核对数量、金额和疑似重复。在相同账户或未标账户的旧流水中，同日同方向同金额，或相同非空审批号，都需要人工核对。此时停止整批导入，不修改既有流水。同一源文件内多笔合法流水可以共用审批号。
6. 在预演通过后使用相同参数和 `apply=True`。正常重跑时 `written` 为零。源账簿更换目标账户、已导入行缺失、已录流水被编辑或余额不一致时，停止，不覆盖。
7. 在页面按公司、人民币和银行科目筛选。核对全期间的每一行和原表截止日余额，不将其他账户或截止日后的交易计入。

正式写入使用 MariaDB InnoDB 事务。导入器在核对期间锁定源账簿和对应的流水范围，提交或回滚时释放锁。其他人此时保存同一范围内的流水可能需要等待。若连接未使用可重复读或串行化隔离级别，导入器会停止；不要为单笔导入更改全站隔离设置。
