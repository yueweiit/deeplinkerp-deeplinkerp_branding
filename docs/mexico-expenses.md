# 墨西哥费用支出工作台

2026-11-16：已在本地测试站点 `dev.localhost` 迁移、构建资源，并按 MX 财务审批通过时间重算已有审批缓存；未部署生产。页面 `mexico-expenses` 位于本 App，沿用 ERP 登录、公司权限、格式化与翻译，独立于中国运营支出和海外采购成本核算。

## 业务范围与口径

工作台在左侧二级导航提供费用概览、费用明细、薪酬人事、统计报表和数据核对五个入口。“统计报表”为原生可折叠分组，包含子公司费用汇总、薪酬人事汇总、月度费用趋势三个子菜单，移除内容区原有横向报表切换栏。复用 Frappe Section Break 的展开/折叠和本地状态保存；进入任一子报表时，由原生侧栏按独立路由高亮子项并展开父级。内容区直接从筛选条件开始，不再重复显示大标题、介绍和横向五页签；“统计口径”保留在右上角菜单。费用承担主体对应 ERP Company；部门仅在管理员明确配置 `department` 类型映射时才可归属公司。映射以主体类型和原始名称形成稳定键，不用可能被复用的钉钉选项 key 单独判定公司。

审批表分为运营支出、费用支出、采购支出。费用支出保留薪酬人事、税费、公用运营、运输物流、专业服务分类；运营支出补充福利、管理费用、销售费用，采购支出细分 MRO、订单、投资、服务和项目采购。薪酬人事包含工资、社保、Fonacot、年终奖、奖金，其余分类见 `services/mexico_expense_contract.py` 的 `CATEGORIES`、`SUBCATEGORIES`。分类使用中立编码；界面和报表以翻译后的标签展示。来源按稳定组件 ID 识别结构，并使用集中维护的历史标签别名识别类别；未知值、歧义和重复字段留待核对。

- 申请金额卡片展示所选口径下的来源明细金额；待核对数据与已确认统计分开。子公司图表、趋势、薪酬和汇总报表仅采用无来源问题且归属、期间已确认的明细。
- 审批状态独立保留 `pending`、`approved`、`rejected`、`terminated`、`withdrawn`、`unknown`。有效申请是审批中及已审批；薪酬及报表默认筛选 `finance_approved`（财务已通过），包含财务通过但整个流程仍在审批中的有效申请。概览、明细及核对默认有效申请。OA 审批通过或存在附件不能证明实际付款。
- 一张审批可以有多家公司和多行费用，金额按行相加，申请数按来源身份去重；不能将整单金额重复计入每家公司，也不能相加各类别的去重申请数作为公司申请数。
- 工作台以“折算币种”选择 MXN、USD 或 CNY，不再按原始币种排除审批；逐笔折算后汇总，原始金额和币种保持不变。每条明细先按两位十进制四舍五入，再汇总；不可解析、负数、超精度或超过 Frappe DECIMAL(21,9) 存储范围的来源金额留待核对；金额不完整时申请金额卡片显示待核对，不以部分金额冒充完整合计。保留 `amount_raw`，不把无效金额显示为 0。
- 费用归属月份自动取模板配置的 MX 财务节点通过时间所在的业务月份；支持精确节点名称及 activityId，默认节点名 `MX财务Finanzas`，旧费用模板额外保留 `f1e6_b1c7`。不使用模糊“财务”匹配认定通过。仅接受 `COMPLETED + AGREE` 的任务；存在相应审批操作时，以唯一匹配、位于任务创建及完成时间之间的 `EXECUTE_TASK_NORMAL + AGREE` 操作时间为准（操作可能早于任务关闭一分钟），没有审批操作时使用任务完成时间。多个有效任务须全部通过，取最后通过时刻。仅转交的任务不代表通过，替代任务仍须完成；未通过、重新审批中、撤回或拒绝的申请不归期，冲突证据进入核对。
- 使用配置的业务时区（默认 `America/Mexico_City`）。例如 9 月申请、10 月财务通过，归入 10 月；不使用申请日、计划付款日或自由文本。所有费用（含工资）按月归期，起止日期为该月首末日，不需逐条填写月份。薪酬报表合并运营与费用两类审批，按子公司、薪酬类别和月份汇总，不涉及员工个人工资。
- 等待财务通过的记录可在核对页按申请日期查找。未分摊的历史多主体整单不能通过单纯选择公司变成已确认费用，需在 OA 修正后同步；金额、币种、分类、结构等来源问题同样不能由人工核对消除。
- 不创建员工、供应商、公司、科目，不生成或提交会计凭证、付款单和 GL。

### 审批表筛选

左侧原生导航上方的“审批表”选择区提供运营支出（`operating`）、费用支出（`expense`）、采购支出（`purchase`）和全部审批表，与薪酬、税费等 `category/subcategory` 独立。Source、Line 都保存只读 `approval_type`；查询仍通过配置的 corpId + processCode 与 Source 关联校验所属审批表。旧请求和分类链接兼容。

审批表选择区支持选中高亮及键盘操作，切换时保留当前页面、日期、子公司、币种和状态，清除类别、搜索及核对问题；不新增重复页面或修改权限。离开工作台时移除该选择区，原生侧栏重建后自动恢复。

全部审批表下，概览构成及子公司汇总按三张审批表分列；选择单一审批表后，构成及统计报表按业务分类展开。明细新增审批表、财务通过日期；详情展示业务分类路径、工资类型、生产属性、执行地区和预算快照（有值时）。采购物品、加工商明细只作支撑信息展示，不再次加入费用金额。

单一审批表的费用构成图例仅展示当前筛选范围内有正金额的已确认费用类别，不重复列出其他审批表的零金额类别；分类颜色和明细下钻编码保持稳定。无可统计金额时显示空状态。全部审批表的构成保留三类审批表对比。

管理员可增添模板、启停、调整财务节点及字段映射；企业须在 OA 连接允许名单内。同一 corpId + processCode 唯一，已有模板不能改审批表或删除，停用仅停止同步，历史记录继续可查。首次迁移仅补齐默认模板一次；后续迁移不重置配置或重新启用已停用模板。旧单模板游标转移至费用支出模板。

每条模板独立保存游标、快照、页数、最后成功时间和错误。新启用或修改解析/财务规则时，从 OA 读取最多三张样本预览；无样本时先保存为停用，结构歧义须修正映射后再启用。预览仅返回数量、问题类型及财务节点名称，不向前端返回原始审批。预览通过不意味着历史所有审批都已确认，逐条同步仍执行完整校验。

字段映射是逻辑字段到组件 ID 数组，如 `{"amount":["MoneyField_new"],"currency":["DDSelectField_new"]}`。已知布局集中在 `services/mexico_expense_templates.py` 的 `FIELDS/EXPENSE_FIELDS`，先按 ID 匹配，再按精确历史标签兼容；显式映射不回退标签。费用支出显式 `amount` 映射优先于旧计算金额；目标缺失、空值、无效或歧义时标记金额待核对，不回退旧金额。表格映射替换对应默认表格，只统计选中的实际组件，保持原始 JSON 与实际组件行身份；被替代的旧行由缓存重算停用并保留历史，其他未覆盖的工资/社保表继续独立处理。已有类似字段/流程的新模板可直接配置；新增业务分类、表格子字段语义或金额分摊规则仍须扩展对应解析器，不自动猜测。财务节点名称逐行配置，多个匹配任务须全部通过。配置语义变更会触发缓存重算，重算前继续沿用旧版本拦截保护。

### 日期范围筛选

工作台使用统一的时间范围选择框，由 `public/js/mexico_expense_date_range.js` 封装 Desk 已加载的 Air Datepicker，桌面并排显示起止日期所在月份，窄屏改为上下排列；同月范围显示前月及当月，右侧始终包含结束日期（1900 年 1 月下界两侧均显示该月），不再固定显示开始月及下一月；沿用站点日期格式、日历语言和每周起始日，不增加依赖。点击两次选定起止日期后一次更新查询，可反向选择或两次选择同日；只选开始日期时不更新结果，点击外部、取消或 Escape 放弃本次未完成选择。支持键盘选日、日期区间高亮，刷新和离开页面销毁弹层与事件。日期口径、子公司、币种和状态使用 Desk 已加载的 Bootstrap 下拉菜单，保留内部筛选编码、原有选项和禁用规则；弹层样式仅限本页，支持选中标记、方向键、Enter/空格选择、Escape 关闭及选择后恢复焦点。

页面使用开始日期、结束日期，首次打开默认业务时区的当月首日至末日，包含两端日期；同一天起止即可查询单日，支持跨月、跨年。费用所属期间口径按业务时区下的 `finance_approved_date` 筛选，而非月初 `period_month`；另两个口径分别使用 `request_date`、`planned_payment_date`。后台拒绝无效日期、缺少任一端、起始晚于结束及超出现有 1900—2200 年边界的范围。

概览、列表、薪酬、三个子报表、原生报表和 Excel 使用同一范围。趋势图和月度趋势报表仅汇总范围内数据，仍按月展示，不再额外包含前五个月；薪酬跨月仍分子公司及月份。点击趋势月份或薪酬月份行，下钻取该月与当前日期范围的交集，避免把区间外的日期带入明细。Excel 筛选说明和文件名包含起止日期。

工作台在同一浏览器、同一站点内按登录用户保存最近一次有效日期范围及审批表（`localStorage`，不保存审批内容），七个页面共用；换设备或浏览器不会同步。恢复优先级为显式 `mx_filters` 链接参数 → 上次选择 → 当月默认值；旧月份链接仍优先。无效日期或存储不可用不覆盖有效偏好，切换账号不共用偏好。有效筛选变动会替换当前 URL 的筛选参数，防止刷新时旧链接恢复之前日期，不新增历史记录。其他筛选仍按页面保留，并随下钻链接传递。

日历底部提供“今天、本月、近三个月、近180天”：今天为单日，本月为首末日，近三个月从三个月前同日到今天（月末不足该日时取月末），近180天包含今天共180天；快捷选择重新读取墨西哥业务日期，仅修改日期。右侧“重置筛选”按最新需求恢复全部默认值：日期回当月、审批表回全部，日期口径、公司、币种、状态、类别、搜索和核对问题恢复为各页面默认值；不再保留旧日期和审批表。操作均重置分页、更新 URL 及保存偏好。

新 API 和 URL 筛选使用 `from_date/to_date`；旧 `month=YYYY-MM` 请求及旧月份链接兼容转换为整月，显式日期范围优先。原生报表保留隐藏月份参数用于旧链接转换。该修改不改变历史费用归期字段，无需新增数据库字段。

## 折算币种与月初汇率

实现入口为 `services/mexico_expense_fx.py`。每笔费用取业务时区下 `finance_approved_date` 所在月份的 1 日汇率；尚未取得财务审批通过日期的按 `request_date` 所在月份 1 日暂估，并在概览、明细及导出标记。日期筛选口径（申请、费用归期、计划付款）只影响选中记录，不改变汇率归期；跨月区间逐笔选取对应月份，不能统一用查询起始月份汇率。缺少财务通过日期的记录仍遵循既有日期筛选及已确认报表准入规则，暂估不会使其进入正式费用报表。

汇率沿用 `overseas_costing.services.fx_rate_service.fetch_cny_rate()` 的服务端接口配置，获取源币种和目标币种同一天的人民币报价，以“源币兑 CNY / 目标币兑 CNY”计算交叉汇率，保留 12 位汇率小数；同币种为 1。仅接收有限、正数且返回日期恰为月初的成功结果。若接口不可用或缺少当日汇率则中止折算并明确报错，不用其他日期、当前汇率或 1 补齐。正向报价按站点、月初日期及币种在 Redis 缓存 24 小时，同一请求按币种和月份复用，不逐明细调用外部接口。复用的是现有读取接口，不使用海外成本模块的历史回退规则，不改写 Currency Exchange 或审批来源。

概览、图表、薪酬、工作台/原生报表、明细与 Excel 共用计算口径。折算模式的工作台及三个原生报表在 HTTP 返回边界将金额转为两位十进制字符串，避免 Frappe 将 Decimal 序列化为浮点数；Python 汇总及导出调用仍保留 Decimal，旧原币 API 契约保持不变。`public/js/mexico_expense_money.js` 供工作台及原生报表共用，大额使用字符串和 BigInt 生成显示值，并沿用 Desk 数字分隔符、币种符号和符号位置配置。工作台 Excel 中超过 15 位有效数字的金额以精确文本保存，其余金额保留数值单元格，避免 Excel 数字精度限制吞掉分位。明细/详情新增 `converted_amount`、`reporting_currency`、`exchange_rate`、`exchange_rate_date`、`fx_date_basis`、`fx_estimated`、`fx_status`，原 `amount/currency` 保持来源事实。明细 Excel 同时导出原币金额、折算金额、汇率、汇率日期、取值口径及暂估标记；汇总导出注明折算规则。未知原币或金额无效时不伪造折算值，概览提示金额不完整，仍需数据核对。

新调用必须显式传 `reporting_currency`，服务端按此跳过原币过滤；已有仅传 `currency` 的 API 调用保留原币筛选契约。工作台 URL 内 `currency` 作为所选展示币种，在请求时补入 `reporting_currency`；原生报表旧币种链接迁移到折算币种，显式新参数优先。未增加数据库字段，无需数据库迁移，原有公司权限、财务角色及导出权限继续适用。

## 来源、同步与附件

费用申请详情顶部提供“打开钉钉原单”，复用 `overseas_costing.utils.dingtalk.build_desktop_approval_url`，以服务器保存的 `process_instance_id` 生成钉钉客户端链接，不使用审批编号代替实例 ID，也不使用来源提供的任意 URL。链接随 `get_detail` 返回，沿用整单全部子公司访问检查；部分公司授权用户不返回链接。此入口无需读取 OA 附件或等待归档，钉钉客户端仍要求登录并校验审批访问权限。实例 ID 缺失或无效、未安装共享链接工具时隐藏入口，不影响费用详情。无需新增字段或迁移。

来源由服务端已保存的模板配置决定。服务器复用 `operating_oa_http.configuration()` 的 OA 地址和企业允许范围。普通查询/附件请求不能指定任意源地址、企业或模板；管理员仅可通过同步设置及预览接口维护授权模板。

`operating_oa_http.read_template_page()` 新增独立模板读取能力，不改变原 `read_page()` 的中国模板和旧游标契约。当前实现每轮做全量分页，每个后台任务处理一页，页完成后持久化游标并在事务提交后排队下一页。它尚未实现 `updatedAfter` 增量水位。

同步默认关闭。管理员可在页面同步设置中启用每 15 分钟的定时同步，也可“立即同步”完成一次分页扫描。每条模板的 Redis 锁与设置、来源、明细数据库锁协调同步和人工核对；单页失败回滚，不推进该模板游标，也不阻断其他模板独立调度。明确的失效游标重置全量扫描；其他失败保留游标等待重试。源记录和明细使用唯一稳定键，重复同步不重复建单，未变化的投影不更新 `modified`。

覆盖通用费用表 `TableField_1QM4FQVMBI0W0`、工资表 `TableField_ENJNMIBMUAO0`、社保表 `TableField_21SE4NJZE8W00` 和旧版表头金额。表头计算总额仅校验，不再次计入金额。明细身份使用审批来源、表格 ID、`rowNumber`；缺失或重复行标识不能进入已确认报表。来源版本更新时移除的明细置为非活动，保留历史；外部明确删除标记按撤回处理。不因一次分页未出现某审批而推断该审批已删除；接口未提供删除事实的缺失记录，本版不自动清除，需管理员核查。

运营审批优先使用明确的表头金额；工资/社保/办公分摊表存在时按行形成费用，并校验与表头合计一致。级联主体 `公司/部门` 仅拆出明确公司层级，仍需显式 Company 映射；普通多选主体不自动拆分。采购审批只生成一条费用，保留物品和加工商明细、校验数量×单价及各表与表头合计。运营、费用、采购三类审批的零金额明细统一列为 `amount_pending`，人工核对不能消除该来源问题，不计入已确认报表。未知类别、重复行、金额差异均进入核对。新建来源/明细时空 Company/Currency 明确保持为空，避免 Frappe 将当前用户默认公司/币种作为审批事实。

人工归属核对与明细事实指纹绑定；主体、金额、币种、分类、说明或表头金额核对事实变化后，旧人工归属失效，标记重新核对。该 `stale` 标记在重复同步、重算和映射更新后持续保留，只有通过 `review_line` 对当前事实人工核对才能解除，不能因旧核对指纹被清空而自动恢复确认。期间每次投影都从财务审批证据重新计算，旧人工月份不能覆盖当前审批月份；仅审批时间或状态变化不清除仍有效的人工公司归属。来源原文保存在受保护的 `raw_json`，人工修改写独立字段并沿用 Frappe Version 留痕。映射变更后异步重新投影缓存，期间旧映射不能进入已确认报表，普通财务人员也不能沿用旧公司范围访问记录。缓存重算任务使用归期规则版本、映射和业务时区组成的独立版本，切换同步开关不会取消已排队或分批执行中的重算；后续映射或时区变更会使旧任务失效。设置保存仍使用包含同步开关的完整配置版本防止覆盖其他人的修改。

附件通过 `GET /api/v1/attachments` 精确查询，内容经 `GET /api/v1/attachment-content` 代理下载。读取前检查来源版本仍与 OA 一致，校验企业、实例、文件 ID、归档状态、大小及 SHA256，下载上限沿用 20 MiB。只有能访问整单全部子公司（包括历史上已移除明细的公司）的人员才能读取整单审批进度与附件；部分公司授权的人员只看到有权限的费用明细及其金额，不能获知其他公司明细、整单金额或审批备注。原始来源地址和下载路径不返回浏览器。

明细保存只读 `period_version`，由归期规则及业务时区及模板解析/财务规则生成，独立于公司映射和同步开关。时区或归期规则改变后，列表、概览、标准报表和导出先检查当前用户可见、符合公司/类别/状态/币种/搜索条件的记录是否全部完成重算；检查不使用尚不可信的旧日期过滤。有待重算记录时明确提示并暂停结果输出，避免混用新旧月份或展示部分汇总。公司手工归属也不能绕过归期版本检查。数据核对仍可读取这些明细，归期字段暂不展示，标记 `period_stale`；费用期间口径下暂按申请日期定位，人工核对提交也须等待重算完成。重算失败时该保护持续有效。

## API 与权限

方法均位于 `deeplinkerp_branding.services.mexico_expenses`，要求登录。`get_context`、`get_lines`、`get_overview`、`get_report`、`get_detail`、`get_attachments` 提供受权限约束的读取；`export_report` 返回 XLSX，`download_attachment` 返回经校验的文件。`save_settings`、`enqueue_sync`、`review_line` 仅接受 POST。

筛选字段为 `from_date/to_date`（YYYY-MM-DD，含起止日期；兼容旧 `month`）、`basis`（`period/request/planned`）、`company`、`approval_type`（`operating/expense/purchase`）、`category`、`subcategory`、`reporting_currency`（折算币种）、`currency`（兼容旧原币筛选）、`status`、`keyword`、`issue`。列表每页最多 100 行；明细导出最多 20000 行。全部汇总、列表、标准报表和导出共用 `_query()`，启用原生查询权限并检查字段读取范围；金额和去重计数在数据库聚合，避免浏览器分页后的局部数据被当成全量。明细列表、详情和导出在序列化时每批读取一次当前映射版本，避免逐行读取设置及映射子表。

三张标准报表保留工作台的分类、子类、搜索词及全部审批状态；分类选项由 `get_context` 的现有字典提供，展示翻译标签、传递稳定编码。薪酬报表固定按费用期间统计人事类别，核对问题筛选与工作台汇总报表一样不参与已确认数据查询。

明细 DocType 为财务用户、财务经理和系统管理员提供 `read/report/export` 权限，满足 Frappe 原生报表入口校验；不授予通用写入权限。财务用户或经理读取已获授权的墨西哥非集团公司；没有映射的记录只向系统管理员开放。只有财务经理/系统管理员可以核对费用行并填写说明；期间由审批证据自动计算，`review_line` 保留旧期间参数但拒绝与自动归期不一致的手工值；改派公司和同步配置仅限系统管理员，并检查目标 Company 的访问权限。同步设置的读取和管理还要求拥有全部已映射公司的权限，受限管理员不会收到其他公司的映射表。人工核对同时校验来源版本和明细 `modified`，拒绝覆盖同步或其他人员的新修改。

来源、明细和设置不开放标准 CRUD 写权限，Controller 的 managed write 检查也保护通用接口、删除和重命名。来源原始 JSON 为更高字段权限，仅后台按授权范围投影；跨公司源记录另有整单公司范围检查。导出检查原生 export 权限，金额写数值单元格，原始文本的公式前缀转义；导出表头、状态及口径支持三语。

## 发布与配置验收

代码准备完成后，在获授权的目标站点按既有发布流程交付 App 版本、构建资源及执行迁移，核对新 DocType、Page、三张 Report、索引、左侧主导航及首页快捷图标。本地测试站点已执行迁移和资源构建；迁移钩子会分批重算已有缓存，无需重新请求 OA 或手工填写期间。

1. 管理员核对 OA 服务配置及模板，打开墨西哥费用工作台的同步设置。
2. 核实主体与真实 Company 的关系，按原名/类型配置。开发站点曾查到 `YUEWEI MX`、`YW MOLDES`、`LEMOS MX`、`UV IMPRESION`、`AmigoMart`、`YW GRUPO MX`，均不能据此自动绑定；未查到同名 `LATINGO MX`，需业务确认，不能猜测它对应哪个公司。
3. 发起一次同步，检查后台任务、分页完成、最近同步时间与错误。先以申请日期看来源，再核对公司映射、分类及财务审批证据；不再逐条填写期间。
4. 用财务用户、财务经理、公司受限的系统管理员和跨公司用户验证列表、图表、报表、导出及整单附件的隔离；验证状态更新、撤回、重同步、映射变化、行移除和并发核对。
5. 在中英西用户语言下验证页面、标准报表和实际 XLSX；以真实工资、社保和通用费用样本核对单号去重、金额、归属月份及明细下钻。再决定是否开启定时同步。
